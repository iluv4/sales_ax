# 인플루언서·전문가 발굴: 속도와 유효 데이터 비교

2026-11-02. Apify와 Claude Code의 체감 속도가 비슷하다는 사용자 관찰을 출발점으로 한다. 아직 동일 조건의 실행 로그를 비교하지 않았으므로 원인과 성능 우열은 확정하지 않는다.

## 비교할 세 가지 업무

| 업무 | 입력 | 출력 |
|---|---|---|
| 후보 발견 | ICP·업종·지역·역할·채널 조건 | 아직 검증하지 않은 고유 후보와 공개 URL |
| 프로필 수집 | 동일한 후보 URL 목록 | 공개 프로필·연락 경로·콘텐츠 메타데이터 |
| 판단·검증 | 수집 결과와 ICP | 적합/부적합/보류, 근거, 공개 연락처 검증 상태 |

서로 다른 업무를 한꺼번에 ‘검색 시간’이라고 부르면 도구 차이를 알 수 없다. Apify에서 검색 결과만 받아오는 시간과 Claude가 근거·메일까지 준비하는 시간을 직접 비교하지 않는다.

## 동일 조건 실험

1. 고객 A의 동일 ICP 버전, 동일 업종·지역·언어·최신성 조건을 사용한다.
2. **발견 실험:** 각 경로에 같은 시간·비용 예산을 주고 고유 신규 후보와 유효 연락처 확보량을 센다.
3. **수집 실험:** 공개 URL 50개를 같은 목록으로 주고 두 경로의 총시간, 누락, 실패, 비용을 비교한다.
4. **평가 실험:** 수집 결과를 같은 평가기로 처리해 수집기와 AI 평가기 성능을 분리한다.
5. 공통 개인정보·중복·연락처·근거 검사 기준을 적용한다. 누락된 값을 모델 추측으로 채우지 않는다.
6. 50→200→2,000개로 키우되 허용된 소스 접근·공급자 한도 안에서 실행한다. 마지막 실험도 실제 메일을 보내지 않는다.

## 결과에 반드시 표시할 값

- 최초 결과까지 시간 / 전체 완료 시간 / 후보당 p50·p95 처리시간
- 고유 후보 수 / 기존 접촉 중복 수 / ICP 적합 수 / 공개 연락처 검증 통과 수
- 사람이 확인한 정답 표본 대비 적합성 오류·연락처 오류·근거 누락
- API·데이터 공급·AI 호출의 실제 비용, 재시도와 실패를 포함한 유효 연락처당 비용
- 사람 검수·수정 시간과 최종 승인 가능한 초안 수
- 시간·비용 예산으로 중단됐는지, 실제 후보가 소진됐는지 구분

핵심 비교 단위는 **검증된 신규 고객 100명을 확보하는 데 걸린 시간·비용·사람 작업량**이다. 총 프로필 2,000개를 반환했다는 사실만으로 성능 우위를 선언하지 않는다.

## 원인 가설과 확인 방법

| 가설 | 확인할 로그 |
|---|---|
| 후보를 찾는 시간이 대부분이다 | 첫 신규 URL 발견까지 시간, 시간당 신규 후보, 검색 범위 확장 횟수 |
| 원본 사이트 응답·접근 제한이 느리다 | 소스별 요청 지연·실패·대기·허용량 |
| 중복·부적합 비중이 높다 | 원시 후보→고유 신규→적합 고객의 감소량 |
| AI가 각 프로필을 길게 읽는다 | 프로필당 읽은 문서·토큰·호출 횟수·평가 시간 |
| 초기 준비 시간이 크다 | 첫 실행과 재실행 차이, 준비 시간과 항목별 처리시간의 분리 |
| 작은 배치라 차이가 감춰졌다 | 동일 조건에서 규모별 처리량 그래프와 오류율 |

가설이 확인되면 해당 단계만 교체한다. 예를 들어 후보 발견이 병목이면 데이터 소스와 인덱스를 먼저 비교하고, 프로필 수집이 병목이면 수집 경로를 비교하고, 평가가 병목이면 공통 근거 재사용·짧은 1차 판별·정밀 조사 분리 등을 검증한다.

## 제품에 반영할 구조

캠페인 ICP → 후보 소스 어댑터 → 정규화·중복/수신거부 검사 → 가벼운 적합 판별 → 통과 후보만 정밀 조사 → 초안/소개서 준비.

웹 검색·수집 도구·크리에이터 데이터 소스 중 하나에 제품 전체를 묶지 않는다. 업체 명성이나 체감이 아니라 실험 결과로 단계별 어댑터를 선택한다. 현재 어떤 경로가 더 빠르다는 측정 결과는 아직 없다.
